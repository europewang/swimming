# 接口对接说明

这份文档用于直接交给后端开发或其他 AI。

目标：

- 为 Android App 提供账号密码登录、注册用户、额度校验、识别会话管理接口
- 所有用户数据都来自后端数据库
- App 每次启动都重新向后端获取用户与额度信息，不能只信任本地缓存

## 1. 服务端口约定

服务器地址：

`43.156.49.149`

端口分工：

- `8085`：Android App 使用的业务接口
- `8086`：后台管理系统使用

Android App 只访问：

`http://43.156.49.149:8085/api/v1`

Android App 不访问：

`8086`

## 2. 总体安全要求

后端必须满足这些要求：

1. 用户账号、密码、昵称、额度等信息全部存数据库
2. Android App 每次启动都要重新调用后端接口校验当前用户是否合法
3. Android App 每次准备开始识别或录制前，都要重新读取额度
4. 扣减额度必须由后端完成，不能只靠前端判断
5. 即使手机本地还保留 token，后端也必须通过 `profile` 和 `quota/summary` 再次确认当前用户状态

## 3. 统一返回格式

所有接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

规则：

- `code = 0`：成功
- `code != 0`：失败
- `message`：错误或提示信息
- `data`：业务数据

请求与响应统一：

- `Content-Type: application/json`
- `UTF-8`

除登录和注册外，其他接口统一要求：

```http
Authorization: Bearer <token>
```

## 4. App 真实业务流程

Android App 当前希望按下面流程工作：

1. 用户输入账号密码登录
2. 或者先注册新用户，再登录
3. 登录成功后，后端返回 token
4. App 立刻请求用户信息
5. App 立刻请求额度信息
6. 只有用户和额度校验成功后，才能进入识别页
7. 进入识别页后创建识别会话
8. 点击开始录制时，再次查询额度
9. 额度足够时，由后端执行扣减
10. 扣减成功后，前端才真正开始录制
11. 识别过程中发送心跳
12. 结束时关闭会话

## 5. 需要实现的接口

统一前缀：

`/api/v1`

## 5.1 用户注册

### `POST /auth/register`

请求体：

```json
{
  "account": "new_user",
  "password": "123456",
  "nickname": "小王"
}
```

成功返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

后端要求：

- `account` 唯一
- `password` 必须存加密后的摘要，不允许明文入库
- 如果账号已存在，返回非 0 `code`

## 5.2 用户登录

### `POST /auth/login`

请求体：

```json
{
  "loginType": "password",
  "account": "demo_user",
  "password": "123456"
}
```

成功返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "userId": 1001,
    "token": "jwt-token",
    "nickname": "test_user",
    "quotaRemain": 87,
    "planType": "trial"
  }
}
```

字段要求：

- `userId`
- `token`
- `nickname`
- `quotaRemain`
- `planType`

## 5.3 获取当前用户信息

### `GET /auth/profile`

请求头：

```http
Authorization: Bearer <token>
```

成功返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {

    "nickname": "test_user",
```

用途：

- App 每次启动都要调用
- 用来确认 token 是否仍然有效
- 用来确认该用户是否仍然有权限

## 5.5 扣减额度

### `POST /quota/consume`

请求体：

```json
{
  "sessionId": "session_20260823_101500_123",
  "consumeType": "swim_track",
  "consumeCount": 1

```

成功返回：

```json
{
  "code": 0,
  "message": "ok",

```

后端要求：

- 必须幂等
- 同一个 `sessionId + consumeType` 不能重复扣减
- 如果额度不足，要返回失败
- 只有这个接口成功后，前端才会真正开始录制

## 6. 数据库最低要求

后端数据库至少需要有：

1. 用户表
2. 用户额度表
3. 用户与设备绑定表
4. 额度扣减流水表
5. 识别会话表

至少要支持：

- 账号密码登录
- 新用户注册
- 查询用户剩余额度
- 扣减额度
- 会话开始/心跳/结束记录

## 7. 推荐 MySQL 建表 SQL

下面这套 SQL 直接对齐当前 Android App 的登录、注册、额度、会话接口，可以直接复制给后端使用。

### 7.1 用户表 `users`

```sql
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  account VARCHAR(64) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  nickname VARCHAR(64) NOT NULL,
  avatar_url VARCHAR(255) NULL,
  status TINYINT NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

说明：

- `account` 唯一，用于登录
- `password_hash` 存加密后的密码摘要
- `status` 可用于禁用账号

### 7.2 用户额度表 `user_quota`

```sql
CREATE TABLE user_quota (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  quota_total INT NOT NULL DEFAULT 0,
  quota_used INT NOT NULL DEFAULT 0,
  quota_remain INT NOT NULL DEFAULT 0,
  plan_type VARCHAR(32) NOT NULL DEFAULT 'trial',
  plan_expire_at DATETIME NULL,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_id (user_id)
);
```

说明：

- 每个用户一条额度记录
- `plan_type` 对应 App 首页显示的套餐
- `plan_expire_at` 对应 App 首页显示的到期时间

### 7.3 设备表 `devices`

```sql
CREATE TABLE devices (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  device_code VARCHAR(64) NOT NULL UNIQUE,
  device_name VARCHAR(64) NOT NULL,
  wifi_ssid VARCHAR(64) NULL,
  mac_address VARCHAR(32) NULL,
  device_type VARCHAR(32) NOT NULL DEFAULT 'esp32_cam',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 7.4 用户设备绑定表 `user_devices`

```sql
CREATE TABLE user_devices (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  device_id BIGINT NOT NULL,
  bind_status TINYINT NOT NULL DEFAULT 1,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_device (user_id, device_id)
);
```

### 7.5 额度扣减流水表 `quota_consume_log`

```sql
CREATE TABLE quota_consume_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  session_id VARCHAR(64) NOT NULL,
  consume_type VARCHAR(32) NOT NULL,
  consume_count INT NOT NULL,
  quota_before INT NOT NULL,
  quota_after INT NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_session_consume (session_id, consume_type)
);
```

说明：

- `uk_session_consume` 用于保证幂等
- 同一个 `sessionId + consumeType` 不能重复扣减

### 7.6 识别会话表 `track_sessions`

```sql
CREATE TABLE track_sessions (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  session_id VARCHAR(64) NOT NULL UNIQUE,
  user_id BIGINT NOT NULL,
  device_code VARCHAR(64) NULL,
  mode VARCHAR(32) NOT NULL,
  video_source VARCHAR(32) NOT NULL,
  app_version VARCHAR(32) NULL,
  started_at DATETIME NOT NULL,
  ended_at DATETIME NULL,
  duration_sec INT NOT NULL DEFAULT 0,
  avg_fps DECIMAL(6,2) NULL,
  result_summary VARCHAR(255) NULL,
  record_file_path VARCHAR(255) NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 7.7 会话心跳表 `track_session_heartbeat`

```sql
CREATE TABLE track_session_heartbeat (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  session_id VARCHAR(64) NOT NULL,
  track_status VARCHAR(32) NULL,
  fps DECIMAL(6,2) NULL,
  recording TINYINT NOT NULL DEFAULT 0,
  esp32_connected TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_session_id (session_id)
);
```

## 8. 直接交给其他 AI 的任务描述

请基于 `43.156.49.149` 服务器，实现一个运行在 `8085` 端口的后端接口服务，接口前缀为 `/api/v1`。要求支持用户注册、账号密码登录、用户信息查询、额度查询、额度扣减、设备绑定、识别会话开始/心跳/结束。所有用户信息与额度必须来自数据库；Android App 每次启动都要重新访问后端获取用户和额度信息；点击开始录制前也必须再次查询并扣减额度；所有接口统一返回 `code/message/data` JSON 结构。`8086` 端口预留给后台管理系统，Android App 不调用。

补充新增需求，请一并实现：

当前系统新增 `ESP32` 设备联网后的 IP 上报能力，不再依赖 Android App 扫描局域网猜测设备地址。

请在现有后端基础上继续增加下面这套接口与数据结构，要求与当前 App 兼容，并方便后续继续扩展。

### 新增目标

1. `ESP32` 连上手机热点或其他网络后，主动把自己的最新局域网 IP、设备编号、在线状态、更新时间上报给后端。
2. Android App 打开首页或进入视频识别页时，优先从后端读取该设备最新 IP。
3. App 后续直接使用 `IP + 固定端口` 访问设备：
   - 抓拍：`http://<ip>/capture`
   - 状态：`http://<ip>/status`
   - 视频流：`http://<ip>:81/stream`
4. 如果设备重新联网、IP 变化，`ESP32` 再次上报，后端覆盖旧 IP。
5. 后端保存设备最近一次在线时间、最近一次 IP、最近一次状态，供 App 获取。

### 建议新增表

```sql
CREATE TABLE device_runtime_status (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  device_code VARCHAR(64) NOT NULL UNIQUE,
  device_name VARCHAR(64) NULL,
  current_ip VARCHAR(64) NULL,
  current_stream_port INT NOT NULL DEFAULT 81,
  current_http_port INT NOT NULL DEFAULT 80,
  online_status VARCHAR(32) NOT NULL DEFAULT 'offline',
  network_type VARCHAR(32) NULL,
  ssid VARCHAR(128) NULL,
  last_seen_at DATETIME NULL,
  last_report_at DATETIME NULL,
  extra_json TEXT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 建议新增接口

#### 1. ESP32 上报运行状态

- `POST /api/v1/device/runtime/report`

请求体：

```json
{
  "device_code": "esp32_cam_001",
  "device_name": "ESP32-CAM-PROV",
  "current_ip": "192.168.247.22",
  "current_http_port": 80,
  "current_stream_port": 81,
  "online_status": "online",
  "network_type": "phone_hotspot",
  "ssid": "abc",
  "report_time": "2026-08-24T23:20:58+08:00"
}
```

返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "accepted": true
  }
}
```

后端要求：

- 如果 `device_code` 已存在，则更新该设备的最新 IP、端口、在线状态、最近上报时间
- 如果不存在，则自动插入一条新设备运行状态记录
- 允许 `ESP32` 高频重复上报，同一设备的最新值始终覆盖旧值

#### 2. App 获取设备最新运行状态

- `GET /api/v1/device/runtime/latest?device_code=esp32_cam_001`

返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "device_code": "esp32_cam_001",
    "current_ip": "192.168.247.22",
    "current_http_port": 80,
    "current_stream_port": 81,
    "online_status": "online",
    "ssid": "abc",
    "last_seen_at": "2026-08-24 23:20:58"
  }
}
```

后端要求：

- 如果设备存在且有最新上报，则返回最新 IP 与状态
- 如果设备不存在或没有有效 IP，则返回 `code != 0` 或 `data = null`
- 建议按 `last_report_at` 判断是否过期，例如超过 `15-30` 秒未上报则可判定为离线

### App 对接要求

后端实现时，请默认支持 Android App 采用下面逻辑：

1. App 首页打开后，先登录用户
2. 登录完成后，请求 `GET /device/runtime/latest`
3. 如果返回设备在线且有 `current_ip`，App 直接用该 IP 打开视频流，不再扫描网段
4. 如果后端返回设备离线或无 IP，App 才进入重新配网或等待设备上线流程
